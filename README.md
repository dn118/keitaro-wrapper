# Keitaro Wrapper

Тестовое для Adrobot. FastAPI, SQLAlchemy, Alembic, SQLite и HTML/JavaScript.

## Запуск

Нужен Python 3.11 или новее. Из корня репозитория:

```bash
python -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
cp .env.example .env
```

В Windows PowerShell вместо `source` и `cp`:

```powershell
.\.venv\Scripts\Activate.ps1
Copy-Item .env.example .env
```

В `.env` укажите:

| Переменная | Значение |
| --- | --- |
| `KEITARO_URL` | Базовый URL трекера, без `/admin`. Допускается URL с `/admin_api/v1`. |
| `KEITARO_API_KEY` | Ключ Admin API из админки Keitaro. |
| `KEITARO_TIMEZONE` | Часовой пояс отчётов Keitaro в формате IANA, по умолчанию `UTC`. |
| `CAMPAIGN_PREFIX` | Префикс тестовых кампаний, по умолчанию `test_belov_`. |
| `DATABASE_URL` | По умолчанию `sqlite:///./keitaro.db`. |

Запустите миграции и приложение:

```bash
python -m alembic upgrade head
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000
```

Интерфейс доступен на [127.0.0.1:8000](http://127.0.0.1:8000), OpenAPI на [/docs](http://127.0.0.1:8000/docs). Приложение рассчитано на локальный запуск одним процессом. Ключ используется только сервером. Для размещения на общем сервере потребуется контроль доступа к интерфейсу и API.

## Проверка сценариев

1. На вкладке **Новая кампания** введите название, например `test_belov_campaign1`, и двухбуквенный код страны, например `UZ`. Выберите домен, группу, источник и оффер по его Keitaro ID. Списки загружаются из трекера.
2. После создания откройте кампанию в Keitaro. У первого потока должен быть фильтр по стране и HTTP-редирект на Google. Второй поток должен срабатывать для остальных переходов и вести на выбранный оффер.
3. На вкладке **Редактор** выберите тестовую кампанию и период. Добавьте второй оффер и проверьте доли 50/50. Удалите его и проверьте долю оставшегося оффера 100%. Изменения применяются к выбранному потоку.
4. Сверьте статистику с отчётом Keitaro за тот же период и в том же часовом поясе. Клики, конверсии, доход, расход, прибыль и ROI приходят из Admin API.

Активные офферы получают равные целочисленные доли. При делении с остатком дополнительные проценты распределяются по возрастанию ID. После удаления последнего оффера поток остаётся без офферов. При одновременном редактировании из двух вкладок устаревший запрос получает HTTP 409.

Кампания создаётся отключённой и активируется после записи обоих потоков. SQLite хранит параметры и состояние операции. Если запись оборвалась, отправьте ту же форму повторно: приложение ищет кампанию по алиасу и дозаписывает недостающие потоки. Данные кампаний, привязки офферов и статистика читаются из Keitaro.

## Миграции и тесты

```bash
python -m alembic current
python -m alembic check
python -m pip install 'pytest>=8,<10'
python -m pytest -q
```

Тесты используют временную SQLite и имитацию Admin API. Они проверяют дозапись кампании после частичного сбоя, редактор офферов, защиту от устаревшего изменения и чтение отчёта. Живой прогон на предоставленном сервере требуется после восстановления доступа.

[Справочник Keitaro Admin API](https://admin-api.docs.keitaro.io/)
